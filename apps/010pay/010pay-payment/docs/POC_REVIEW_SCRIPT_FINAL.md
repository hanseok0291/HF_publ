## 🎤 슬라이드별 스크립트

### 1. 커버
```
안녕하세요.
오늘은 Figma MCP를 활용한 AI 퍼블리싱 POC 리뷰를 진행하겠습니다.
```

---

### 2. 목차
```
오늘은 6가지 내용으로 진행하겠습니다.
현재 퍼블리싱에서 겪는 문제,
AI 퍼블리싱 도입 배경,
POC 목표와 범위,
작업 프로세스와 데모,
결과와 인사이트,
그리고 개선점입니다.
```
**시간**: 30초

---

### 3. 현재 퍼블리싱 문제 & AI 도입 배경
```
먼저, 현재 퍼블리싱에서 겪는 문제입니다.

첫째, 반복 작업이 많습니다.
구조 패턴을 반복해서 작성하고,
스타일 코드를 반복합니다.

둘째, 리소스가 부족합니다.
개발과 디자인 리소스는 한정적인데,
해야 할 작업, 관리해야 할 페이지는 계속 늘어나고 있습니다.

셋째, 시간이 많이 소모됩니다.
페이지당 약 3시간이 소요되고,
수정 및 가이드 반복에 시간이 많이 걸립니다.

결국, 개발과 디자인 리소스는 한정적인데
해야 할 작업은 계속 늘어나고 있는 상황입니다.

이런 문제를 해결하기 위해 AI 퍼블리싱을 도입하기위해 POC를 진행하였습니다.

왜 AI 퍼블리싱을 도입하는가에 대해서는 
우선 첫째, 생산성 향상이 필요합니다.
반복 작업을 자동화하고, 작업 시간을 대폭 단축하려고 합니다.

둘째, 일관성 유지가 필요합니다.
프로젝트 표준을 자동으로 준수하고, 코드 품질을 향상시키려고 합니다.

셋째, 빠른 프로토타이핑이 가능합니다.
디자인 확인 후 즉시 코드를 생성하고, 피드백 루프를 단축하려고 합니다.

넷째, 리소스 효율화가 필요합니다.
개발자 시간을 더 중요한 작업에 집중시키고,
디자이너와 개발자 간 협업을 개선하려고 합니다.
```
**시간**: 2분

---

### 4. POC 목표와 범위
```
이번 POC의 목표는 4가지입니다.

첫째, Figma 디자인을 AI가 얼마나 빠르게 코드로 옮길 수 있는가?
둘째, .cursorrules 기준을 어느 정도 자동으로 지킬 수 있는가?
셋째, 반복 작업을 얼마나 줄일 수 있는가?
넷째, 실제 서비스 화면에 적용 가능한가?

```
**시간**: 1분

---

### 5. 테스트 범위
```
테스트한 페이지는 4개입니다.
사전알림 페이지, 캐릭터 만들기, 만들기 중 화면, 완성 화면입니다.
```
**시간**: 20초

---

### 6. 기존 작업 프로세스
```
기존 작업 프로세스를 보면,
디자인 분석 30분, HTML 구조 작성 30분, CSS 스타일링 30분,
인터랙션 추가 30분, 테스트 및 수정 1시간으로
총 약 3시간이 소요됩니다.
```
**시간**: 30초

---

### 7. Figma AI 사용 프로세스
```
Figma MCP를 사용하면,
Figma에서 컴포넌트 선택 1분, AI에게 구현 요청 2분,
생성된 코드 검토 및 수정 10분, 인터랙션 추가 15분,
최종 검수 15분으로 총 약 43분이 소요됩니다.

기존 3시간에서 43분으로 약 78% 시간이 단축되었습니다.
```
**시간**: 1분

---

데모 작업 프로세스를 간단하게 보여드리겠습니다.

먼저 완료된 디자인 페이지에서 DEV 모드 활성화 한 뒤 우측 검사탭의 MCP 서버 활성화 버튼으로 서버를 실행시킵니다. 
그 후 커서의 설정 메뉴에서 커서 세팅 - mcp 탭 - mcp 서버생성 - 생성된 mcp 서버 토글하여 on 상태로 만들어 피그마 mcp 서버와 커서를 연결 시키면 준비가 완료됩니다.

작업전에 AI COE에서 전달받은 커서룰스 설정을 보여드리겠습니다. 
이 설정은 프로젝트 최상위에 추가하여 AI가 코드를 생성할때 해당 룰을 기준으로 코드를 생성하게 합니다.

작업은 피그마에서 작업할 컴포넌트를 선택한 뒤 커서의 ai 채팅창에 해당 컴포넌트를 구현해달라고 명령합니다. 그리고 잠시 뒤 완성된 산출물을 확인합니다 페이지 하나당 1-2분정도로 빨리 생성됩니다.

```

### 9-12. 결과 화면
```
실제로 생성된 결과물입니다.
디자인과 거의 일치하게 생성되었고,
프로젝트 구조도 자동으로 올바르게 생성되었습니다.
```

### 13. 시간 관점 변화
```
결과와 인사이트에서 우선 시간 관점에서의 변화입니다.

페이지당 작업 시간은 78% 감소했습니다.
3시간에서 43분으로 줄었습니다.

이미지 추출 시간은 83% 감소했습니다.
기존에는 동일한 이미지가 있는지 확인도 필요했고 한개씩 추출을 해서
시간이 소요되었는데 피그마 MCP를 사용하면서 30분에서 5분으로 줄었습니다.
현재 제대로 추출하지 못하는 이미지들이 있어서 이부분은 디자인팀과 협의하여 설정을 맞춰보려고 합니다.

코드 일관성 검수 시간은 50% 감소했습니다.
수동 검수 40분에서 자동 준수 20분으로 줄었습니다.

반복 작업 시간도 50% 감소했습니다.
90분에서 45분으로 줄었습니다.
```
**시간**: 1.5분

---

### 14. 결과와 인사이트
```
인사이트는 3가지입니다.

첫째, AI는 구조, 사람은 디테일입니다.
AI가 기본 구조를 빠르게 생성하지만, 디테일은 사람이 담당하는 조합이 최적입니다.

둘째, .cursorrules로 프로젝트 표준 자동 준수입니다.
프로젝트 표준을 자동으로 준수할 수 있음을 확인했습니다.

셋째, 반복 작업 자동화, 복잡한 인터랙션은 수동입니다.
이미지 경로, 구조 패턴은 자동화 가능하지만, 복잡한 인터랙션은 여전히 수동 작업이 필요합니다.
```
**시간**: 2분

---

### 15. 개선점
```
개선점은 3가지입니다.

첫째, 이미지 추출 최적화입니다.
현재는 수동 3배수 추출을 하고있는데, 자동 3배수 추출 설정을 목표로 합니다.

둘째, 상세 간격 조정입니다.
현재 .cursorrules 설정이 디테일하지 못해 기본 간격만 자동 적용되거나 겹치는 부분이 생기는데, 상세 간격 규칙을 추가하겠습니다.

셋째, 타 프로젝트 확대 적용입니다.
현재 전용통장 플로우만 적용했는데, 프로젝트별 .cursorrules 템플릿을 만들어 타 프로젝트에도 확대하겠습니다.
```
**시간**: 1.5분
