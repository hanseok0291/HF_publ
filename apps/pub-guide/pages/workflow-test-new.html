test3/4/5 vs _new · Figma-퍼블 수정 협업

test3.html · test4.html · test5.html은 피그마 기반 초안이고, test3_new.html · test4_new.html · test5_new.html은 디자이너·퍼블 정합 후 수정하는 작업본입니다. 이슈를 지정하면 구현 이유와 피그마 수정 가이드를 정리하고, 반영된 시안으로 _new만 갱신합니다.

파일 대응표

기존 (피그마 초안) 수정본 (_new)
test3.html test3_new.html
test4.html test4_new.html
test5.html test5_new.html

진행 순서

1. 이슈 지정 — 아래 체크리스트를 채워 기존 HTML에서 구간을 알려줍니다.

2. 분석·가이드 — 코드·주석 근거로 왜 그렇게 구현됐는지 설명하고, 디자이너가 피그마에서 손볼 항목을 제안합니다.

3. 피그마 반영 — 디자이너가 시안을 수정·토큰화합니다.

4. _new 구현 — 확정 시안에 맞춰 _new 파일만 마크업·스타일을 정합합니다.

이슈 지정 시 포함하면 좋은 정보

  • 파일: test3 / test4 / test5 중 어떤 페이지인지
  • 구간: 클래스명, 섹션 주석(예: <!-- [step1] -->), 또는 HTML 일부·줄 번호
  • 기대 동작: “풀폭이어야 함”, “간격이 DS 토큰과 맞아야 함” 등 한 줄 요약
  • 피그마: 프레임 이름, 노드 링크, 또는 HTML 주석에 있는 fileKey:nodeId 형태 참조
  • 캡처(선택): 시안과 퍼블이 어긋난 부분 스크린샷

디자이너용 · 피그마 수정 시 참고 체크리스트

퍼블이 고정 픽셀·추정값을 쓰지 않도록, 시안에서 아래를 명확히 해 두면 _new 작업이 단순해집니다.

  1. 레이아웃: 콘텐츠 컬럼은 시안·그리드에 맞는 좌우 인셋(패딩 등)으로 정의하고, 그 안 블록은 Fill(100%)인지·아니면 시안에 명시된 고정 폭 컴포넌트인지 프레임 단에서 구분합니다. 인셋 수치·가용 폭은 화면마다 다를 수 있으므로 특정 px(예: 16·343)에 고정해 해석하지 않습니다.
  2. Auto layout: 세로 스택은 gap 대신 퍼블 가이드에 맞는 간격 토큰(8·12·16·20·24·32·40)으로 정리합니다.
  3. 타이포·컬러: 가능하면 디자인 시스템 텍스트 스타일·시맨틱 컬러에 연결합니다.
  4. 복합 UI: 스테퍼·차트·드롭다운 등은 “열림/닫힘” 상태를 별도 프레임으로 두거나 스펙을 메모합니다.
  5. 에셋: 보내기 필요 SVG/PNG는 슬라이스·이름 규칙을 통일합니다.
  6. OS 상태바: 웹 퍼블에는 포함하지 않습니다. GNB(헤더)부터 프레임을 맞춥니다 (00-core).
