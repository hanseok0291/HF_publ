# 빠른 프로토타이핑 리뷰 스크립트

## 📋 슬라이드 내용

**빠른 프로토타이핑**
- 디자인 확인 후 즉시 코드 생성
- 피드백 루프 단축

---

## 🎤 리뷰 스크립트 제안

### 옵션 1: 실제 사례 중심 (권장 ⭐⭐⭐)

**스크립트**:

```
"빠른 프로토타이핑"이라는 것은, 
디자이너가 Figma에서 디자인을 완성하고 
"이거 구현 가능해요?"라고 물어봤을 때,
기존에는 "네, 내일까지 작업해볼게요"라고 답했지만,
이제는 "지금 바로 확인해볼게요"라고 답할 수 있다는 의미입니다.

실제로 이번 POC에서도 그랬는데,
Figma에서 컴포넌트를 선택하고 AI에게 "구현해줘"라고 요청하면
2분 만에 기본 구조와 스타일이 생성됩니다.
그래서 디자이너가 "이 간격이 좀 이상한데?"라고 하면,
"아, 지금 바로 수정해볼게요"라고 답하고
1-2분 내에 수정된 결과를 보여줄 수 있어요.

이게 바로 "피드백 루프 단축"입니다.
기존에는 디자이너 피드백 → 개발자 작업 → 결과 확인까지
하루나 이틀이 걸렸다면,
이제는 몇 분 내에 가능해졌어요.
```

**시간**: 약 1-1.5분

---

### 옵션 2: Before/After 비교 중심 (권장 ⭐⭐)

**스크립트**:

```
"빠른 프로토타이핑"의 핵심은 시간입니다.

기존 방식에서는:
1. 디자이너가 Figma에 디자인 업로드
2. 개발자가 디자인 분석 (30분)
3. HTML/CSS 작성 (2-3시간)
4. 결과 확인 및 피드백 반영 (추가 1-2시간)

총 소요 시간: 하루 이상

하지만 Figma MCP를 사용하면:
1. Figma에서 컴포넌트 선택 (1분)
2. AI 코드 생성 (2분)
3. 결과 확인 및 수정 (10분)

총 소요 시간: 약 15분

이렇게 하면 디자이너가 "이 색상이 좀 어색한데?"라고 하면,
"지금 바로 바꿔볼게요"라고 답하고
몇 분 내에 수정된 결과를 보여줄 수 있어요.

이게 바로 "피드백 루프 단축"입니다.
기존에는 피드백 → 수정 → 확인까지 하루가 걸렸다면,
이제는 몇 분 내에 가능해졌어요.
```

**시간**: 약 1.5-2분
